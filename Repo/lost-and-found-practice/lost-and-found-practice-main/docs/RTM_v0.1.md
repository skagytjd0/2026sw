# 교내 분실물 관리 서비스 요구사항 추적표 RTM v0.1

이 문서는 [고객 요구사항](고객%20요구사항.md)의 고객 요구(NEEDS), 개발 범위(SC), 공통 제약(C_1)을 [요구사항 명세서](SRS_v0.1.md)의 기능 요구사항(FR), 비기능 요구사항(NFR), 정책(Pol)과 연결한다. 추적표의 ID는 01부터 순서대로 부여했다.

| ID | 고객 요구사항/범위 | 출처 및 요약 | SRS 대응 | 추적 결과 및 비고 |
|---|---|---|---|---|
| 01 | NEEDS_1 / SC1 | S1: 방문 전에 분실물 보관 여부와 위치를 확인하고 싶음. SC1 포함 | FR_00, FR_01 | 대응됨. 검색 조건과 공개 항목은 TBD_00 |
| 02 | NEEDS_2 / SC2 | 습득 학생은 습득 물품을 앱으로 바로 등록하고, 행정 담당자는 센터 접수 물품을 관리하기 위해 등록. SC2 포함 | FR_03, FR_06, FR_04 | 두 등록 경로 모두 반영됨. 등록 경로별 필수 항목·인증·승인·권한은 TBD_01 및 UC Q_01~Q_03 |
| 03 | NEEDS_3 / SC3 | S2: 보관 중·인도 완료 상태를 기록하고 구분해야 함. SC3 포함 | FR_05, FR_04, Pol_04 | 대응됨. 인도 및 정정 조건은 TBD_02 |
| 04 | NEEDS_4 / SC6 | S5: 보관 담당 부서에 문의할 방법을 알아야 함. SC6 포함 | FR_02, Pol_07 | 대응됨. 문의 경로와 표시 내용은 TBD_03 |
| 05 | NEEDS_5 / SC4 | S3: 습득물을 맡길 장소를 알고 싶음. SC4 미정 | 해당 없음. TBD: 서비스 범위 편입 여부 결정 | 미결정. 현재 SRS의 기능 요구사항으로 확정하지 않음 |
| 06 | NEEDS_6 / SC8 / C_1 | S4·S5: 공개 정보 범위를 정하고 개인 휴대전화 번호를 공개하지 않음. 학교 인증 연동도 제외 | Pol_00~Pol_03, Pol_07 | 정책 반영됨. 공개 항목의 세부 범위는 TBD_00 |
| 07 | NEEDS_7 | S2: 행정 담당자의 등록 부담을 줄여야 함 | NFR_03 | 부분 대응. 건당 2분 이내는 초기 제안 목표이며 현재 업무 대비 개선율은 기준값 측정 후 확인 필요 |
| 08 | SC5 | S5: 사진 업로드 및 유사 분실물 조회. 개발 범위 제외 | Pol_05 | 제외 범위로 추적됨 |
| 09 | SC7 | S5: 사진 매칭 결과 자동 알림. 개발 범위 제외 | Pol_06 | 제외 범위로 추적됨 |
| 10 | C_1 | 공통 제약: 가상 데이터를 사용하고 실제 개인정보 및 학교 인증 연동은 제외 | Pol_00~Pol_02 | 정책 반영됨 |
| 11 | SC2·SC3 | 등록 및 상태 관리 업무의 응답 시간 요구는 고객 문서에 수치로 제시되지 않음 | NFR_01, NFR_04 | SRS의 초기 제안 목표. 고객 요구에서 직접 도출된 수치가 아님 |
| 12 | 서비스 운영 품질 | 고객 문서에 가용성 목표는 명시되지 않음 | NFR_02 | SRS의 초기 제안 목표. 운영 책임자 검토 필요 |

## 추적성 점검

| 점검 항목 | 결과 |
|---|---|
| 포함된 핵심 범위(SC1~SC3, SC6) | FR 또는 정책으로 연결됨 |
| 제외 범위(SC5, SC7, SC8) | 정책으로 제외 사실을 기록함 |
| 미정 범위(SC4) | SRS 요구사항으로 확정하지 않고 결정 필요 사항으로 표시함 |
| 공통 제약(C_1) | 정책 Pol_00~Pol_02에 반영됨 |
| 새로 제안한 비기능 목표 | NFR_00~NFR_04는 고객 원문에 수치가 없어 초기 제안값으로 구분함. 운영 이해관계자 확인 필요 |
